# ผลตรวจความปลอดภัย

ตรวจเมื่อ 5 พฤศจิกายน 2026 จากการอ่านโค้ดและเทสอัตโนมัติ ยังไม่ได้ผ่านการทดสอบเจาะระบบโดยบุคคลภายนอก

## ปัญหาที่พบและแก้แล้ว

| ระดับ | ปัญหา | การแก้ |
|---|---|---|
| สูง | อีเมลปลอมแนบ header `Authentication-Results` ของตัวเองได้ ทำให้ระบบอาจเปลี่ยนสถานะบัญชีตามอีเมลปลอม | ใช้เฉพาะ header บนสุดจาก `mx.google.com` และ DMARC ต้องผ่านด้วยโดเมนเดียวกับผู้ส่ง |
| กลาง | อีเมลที่มี `From` หลายบรรทัดอาจทำให้ตรวจผู้ส่งผิด | ถือเป็นผู้ส่งที่ไม่รู้จัก |
| กลาง | เส้นทาง login และ OAuth callback ไม่จำกัดอัตราการเรียก | จำกัด 20 ครั้งต่อนาทีต่อ IP |

## สิ่งที่ตรวจแล้ว

| เรื่อง | สถานะ |
|---|---|
| Login เฉพาะอีเมลใน allowlist ที่ Google ยืนยันแล้ว | มีเทส |
| Dev login ใช้ใน production ไม่ได้ ระบบจะไม่ยอมเริ่มทำงาน | มีเทส |
| Session token เก็บเป็น SHA-256 และ cookie เป็น HttpOnly, Secure, SameSite=Lax | มีเทส |
| ทุกเส้นทางข้อมูลต้อง login และงานสำคัญจำกัดเฉพาะ admin | มีเทส |
| ปฏิเสธคำขอแก้ข้อมูลจาก Origin อื่น | มีเทส |
| OAuth token เข้ารหัส AES-256-GCM และไม่ส่งออกทาง API | มีเทส |
| OAuth callback ตรวจ state และบัญชี Google ต้องตรงกับเมล | มีเทส |
| ยืนยันว่าบัญชี Meta มีสิทธิ์จัดการ Page ก่อนเชื่อม | มีเทส |
| อ่าน Gmail แบบ metadata เท่านั้น ไม่เก็บเนื้อหาอีเมล | มีเทส |
| ส่งออก CSV กันสูตร Excel | มีเทส |
| Log ไม่มี query string ซึ่งอาจมี OAuth code | อ่านโค้ด |
| HTTPS, HSTS, CSP และ header ป้องกันอื่น ๆ ผ่าน Caddy | ทดสอบบนเครื่องด้วย `localhost` |
| ฐานข้อมูลและ API ไม่เปิด port ออกนอก Docker | ทดสอบบนเครื่อง |

## ความเสี่ยงที่ยังเหลือ

- CSP ต้องอนุญาต `unsafe-inline` เพราะ Next.js ใส่ inline script จึงกัน XSS ได้ไม่เต็มที่ ความเสี่ยงลดลงเพราะ React escape ข้อมูลให้ และ cookie เป็น HttpOnly
- ยังไม่มีเครื่องมือเปลี่ยน `TOKEN_ENCRYPTION_KEY` ถ้ากุญแจรั่ว ให้ตั้งกุญแจใหม่ แล้วเชื่อม Gmail และ Facebook ใหม่ทั้งหมด
- ไฟล์สำรองไม่ได้เข้ารหัสทั้งไฟล์ และมีข้อมูลส่วนบุคคล ต้องเก็บในที่จำกัดสิทธิ์
- ประวัติการแก้ไขและ metadata ของอีเมลยังไม่มีกำหนดลบอัตโนมัติ ควรกำหนดระยะเวลาเก็บให้สอดคล้องกับ PDPA ก่อนใช้กับข้อมูลคนนอกทีม
- ผู้ใช้ทุกคนในระบบเห็นข้อมูลเจ้าของบัญชีทั้งหมด ยังไม่มีการแบ่งสิทธิ์ตามทีม

## ขอบเขตการใช้งาน

ระบบไม่สมัครบัญชีแทนคน ไม่ปลอมตัวตน ไม่แก้ CAPTCHA และไม่หลบการตรวจจับของแพลตฟอร์ม เจ้าของบัญชีแต่ละคนต้องยินยอมและปฏิบัติตามข้อกำหนดของ Shopee และ Meta เอง
