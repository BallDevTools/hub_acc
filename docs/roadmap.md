# Roadmap

แต่ละเฟสจบด้วย GitHub Release 1 เวอร์ชัน และต้องผ่านเกณฑ์จบของเฟสก่อนเริ่มเฟสถัดไป

| เฟส | งานหลัก | Release |
|---|---|---|
| 1 | ฐานระบบ ทะเบียนบัญชี และ Dashboard สถานะ | v0.1.0 |
| 2 | Onboarding, Page Kit และ Mail Watcher | v0.2.0 |
| 3 | คิวโพสต์และสถิติจาก Meta | v0.3.0 |
| 4 | Report และการแจ้งเตือน | v0.4.0 |
| 5 | เตรียมใช้งานจริงและ deploy | v1.0.0 |

## เฟส 1: ฐานระบบ

**ต้องเตรียม:** Google OAuth client สำหรับ login

- [x] ตั้ง pnpm monorepo, TypeScript, lint และ test
- [x] ตั้ง Postgres ด้วย Docker Compose และ Prisma migration
- [x] สร้างโครง Next.js + Tailwind, Fastify และ worker
- [x] ตั้ง CI บน GitHub Actions และยืนยันว่ารันผ่าน
- [x] ทำ allowlist และ role แบบ admin/member
- [ ] ทดสอบ Google login กับ Google OAuth client จริง (เขียนโค้ดแล้ว)
- [x] ทำ CRUD ของเจ้าของบัญชี เมล บัญชีแพลตฟอร์ม และ Page
- [x] เก็บเฉพาะลิงก์ไปยังรายการใน password manager
- [x] บันทึก audit log เมื่อข้อมูลเปลี่ยน
- [x] ทำ Dashboard แสดงจำนวนตามสถานะ พร้อมค้นหาและกรอง

**เกณฑ์จบ:** login ได้เฉพาะคนใน allowlist, เพิ่มและแก้บัญชีได้, สถานะบน Dashboard ตรงกับข้อมูล, ดูประวัติการแก้ไขได้ และ CI ผ่าน

## เฟส 2: Onboarding และ Mail Watcher

**ต้องเตรียม:** สิทธิ์ Gmail API และ Claude API key

- [ ] ทำ template checklist ของ Shopee Affiliate และ Facebook Page
- [ ] สร้างงานอัตโนมัติเมื่อเพิ่มเจ้าของบัญชี พร้อมผู้รับผิดชอบและกำหนดส่ง
- [ ] ทำปุ่มเปิดหน้าสมัครและคัดลอกข้อมูลทีละช่อง
- [ ] ทำ Page Kit สำหรับร่างชื่อ คำอธิบาย และโพสต์แรก
- [ ] เชื่อม Gmail แบบอ่านอย่างเดียว และเข้ารหัส token
- [ ] จัดประเภทอีเมลอนุมัติ ปฏิเสธ และระงับ
- [ ] กันอีเมลซ้ำ และส่งรายการที่ไม่มั่นใจเข้าคิวตรวจ

**เกณฑ์จบ:** เริ่มจากเพิ่มเจ้าของบัญชีจนได้ checklist ครบ, อีเมลตัวอย่างอัปเดตสถานะถูกต้อง, อีเมลซ้ำไม่ทำให้สถานะเปลี่ยนซ้ำ และอีเมลที่ไม่มั่นใจไม่เปลี่ยนสถานะเอง

## เฟส 3: คิวโพสต์และสถิติ

**ต้องเตรียม:** Meta App และ Page สำหรับทดสอบ

- [ ] เชื่อม Page ที่ผู้ดูแลให้สิทธิ์ผ่าน Meta OAuth
- [ ] ทำคลังคอนเทนต์และขั้นตอนอนุมัติ
- [ ] ทำปฏิทินและคิวโพสต์แยกตาม Page
- [ ] ทำ retry, จัดการ rate limit และกันโพสต์ซ้ำ
- [ ] ดึงสถิติ Page รายวันลง `metrics_daily`
- [ ] แจ้งเตือนเมื่อโพสต์ล้มเหลวหรือ token หมดอายุ

**เกณฑ์จบ:** โพสต์ที่อนุมัติแล้วขึ้น Page ทดสอบตรงเวลา, การ retry ไม่ทำให้โพสต์ซ้ำ, โพสต์ที่ล้มเหลวแสดงสาเหตุ และสถิติรายวันเข้าระบบ

## เฟส 4: Report และการแจ้งเตือน

**ต้องเตรียม:** ไฟล์ report ตัวอย่างจาก Shopee และช่องทางแจ้งเตือนที่ต้องการ

- [ ] นำเข้า CSV ของ Shopee พร้อมตรวจข้อมูลและกันการนำเข้าซ้ำ
- [ ] จับคู่ยอดกับ Page ผ่าน Sub ID
- [ ] ทำ report รายวัน รายสัปดาห์ และรายเดือนแยกตาม Page
- [ ] แสดงบัญชีและงานที่ค้างเกินกำหนด
- [ ] ส่งสรุปประจำวันและการแจ้งเตือนสำคัญ
- [ ] ส่งออก report เป็น CSV

**เกณฑ์จบ:** นำเข้าไฟล์เดิมซ้ำแล้วยอดไม่เพิ่ม, ยอดใน report ตรงกับไฟล์ต้นทาง, รายการที่จับคู่ไม่ได้ถูกแสดงแยก และได้รับสรุปประจำวันตามเวลา

## เฟส 5: ใช้งานจริง

**ต้องเตรียม:** VPS และโดเมน

- [ ] สร้าง Docker image สำหรับ production และตั้งค่า HTTPS
- [ ] ตั้ง backup ฐานข้อมูลอัตโนมัติ และทดสอบ restore
- [ ] ตั้ง logging, health check และการแจ้งเตือนเมื่อระบบล่ม
- [ ] ตรวจความปลอดภัยของ auth, สิทธิ์ และการเก็บ token
- [ ] เขียนคู่มือ deploy, rollback และการใช้งาน

**เกณฑ์จบ:** deploy จาก release ได้ตามคู่มือ, restore จาก backup ได้จริง, rollback ได้ และไม่มีปัญหาความปลอดภัยระดับร้ายแรงค้างอยู่

## เลือกทำภายหลัง

- สร้างและดูแลเมลผ่าน Google Admin API ซึ่งต้องใช้ Google Workspace
- ดึงยอด Shopee อัตโนมัติ เมื่อยืนยันได้ว่ามีช่องทางทางการที่บัญชีใช้ได้
